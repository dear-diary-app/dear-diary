# Private DDAI and AI controls

Typing /ddai- does not invoke AI or send text. Pressing Send intercepts the command before every shared-message path and opens a private dialog. DDAI must be enabled in Settings; its default is off. A short first-use notice requires Continue, then Ask privately makes the request. No answer-to-chat shortcut in this version. Prompt and answer live only in component memory; closing, leaving chat or reloading removes the answer. The composer question remains for retry. Typing signals are suppressed while the composer is a DDAI command. Shared Schedule/effect paths are blocked for the command.

Independent per-account Translate AI and DDAI switches are stored in ai_preferences with owner-only RLS. Existing Translate defaults on; DDAI defaults off. Clients fail closed on unreadable settings. Backend authenticates and checks the feature before quota or provider access, so disabled requests neither reach Cloudflare nor consume quota. Off cannot recall already-sent requests; local in-flight work aborts when settings reload. A request already in processing may finish at the provider.

The existing translate-draft function now accepts strict mode ddai with text only, or existing text/target translation. Same Cloudflare token/model, direct stateless endpoint, store:false, no history/profile/reply context or user IDs forwarded. Same claim_draft_translation counter: 5/min and 30/UTC day per person across both features, with provider free allowance possibly tighter. Failed attempts after quota claim still count. Quota stores counts only; no prompt/answer table, logging or cache added. DDAI has no tools, browsing or live source verification. Treat answers as AI output that may be wrong.

Synthetic actual ChatView/Settings tests passed 320/390/820 paper/midnight: disabled no request, switches independent, first-use consent, explicit Ask, payload text only, no chat send, temporary answer removed, shared limit message, Escape/Back and no overflow. Translate off blocks request and on retains its consent/application flow. Backend mock tests verify both modes share quota and disabled features stop before provider/counter; strict schema and no history/user ID. Live backend v3 returned a DDAI response for a disposable synthetic pair, rejected DDAI default-off and Translate-off; both disposable users were deleted. No real accounts, chat rows, PINs or push subscriptions changed. No physical-phone testing.
