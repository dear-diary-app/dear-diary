# Opening unread divider

On opening chat, snapshot the IDs of unread incoming messages before enabling the existing seen-marking effect. The divider is before the first of those messages and uses the snapshot count, so a receipt update does not make it disappear immediately. Initial position takes priority over saved place, with the divider visible. If the first loaded row is unread and more history is available, fetch backward until the boundary is found. A no-progress guard avoids looping on a failed history request; in that case only the loaded unread count can be shown. No new backend changes.

The first pointer tap, touch scroll gesture, wheel, scroll keyboard action, or composer change after the captured messages have been seen removes the divider. Programmatic positioning does not dismiss it. State is component-only; new arrivals during the visit do not recreate it. Existing seen RPC, new-below counting, notifications and Bubbles visibility observation are retained. Seen marking waits only for boundary capture, not user interaction.
