# Private stories

Home has two left-aligned theme-colored story circles between header and books. Own empty circle opens MP4 picker; an active circle opens an authenticated video viewer with controls. Own viewer offers replace/delete. Preview precedes Post. No autoplay/audio on opening. One active story per linked account, 60 seconds max, 20 MiB cap. Storage metadata before build totaled 8,991,252 bytes across 33 existing objects. New bucket is private with a 20 MiB limit and video/mp4 MIME restriction.

Browser checks actual playable duration before preview. Oversize files attempt a local canvas/MediaRecorder MP4 compression only where both MP4 encoding and captureStream are available. Otherwise the user gets a smaller-file request. Output is checked again; nothing is trimmed or uploaded automatically. Device encoding support varies and real-phone audio retention/compression quality are unverified. Upload validates MP4 ftyp and movie/track duration headers again on the server. It rejects malformed/unknown-duration/over-60-second headers, not a full codec-security audit or transcoding service.

Publication is through authenticated story-media only. JWT establishes owner; service-only story_publish requires a linked partner, valid owner path, existing upload and valid duration. Existing row is replaced only after upload and validation succeed. stories RLS permits only owner and linked partner while expires_at > now(). User storage policies permit no direct reads/uploads/signing, so clients cannot create signed links that outlive expiry. The media function checks viewer relation and expiry, downloads through service role and rechecks expiry before returning no-store MP4 bytes. Already downloaded bytes/screenshots/copies cannot be remotely erased. The frontend closes a playing story on expiry and pauses when hidden.

At expiry reads stop immediately. A minute cron deletes expired rows, queues their paths, and calls the cleanup function with the existing cron secret. Files are removed through Storage API. Removal failures leave queue entries for retry. Replacement/deletion queues old files too. Orphans older than one hour are queued by the same tick. Physical deletion can lag by the minute cadence or longer during outages. No push notifications added. No theme-color/safe-area changes.

Validation: rollback-only database tests with synthetic IDs checked owner/partner/outsider RLS, immediate expiry denial, forbidden client publish/direct Storage read, failed replacement preserving old and delete cleanup queue. Actual disposable auth users tested publish, owner/partner authenticated download, outsider 404 and expired 404. All synthetic users/files removed. Deployed cleanup actually removed a separate disposable video via Storage API. UI mocks at 390 and 820 pixels previewed/posted/played a 2-second generated MP4, no overflow, circles in correct strip. Screenshots inspected. Real phone/partner-device playback and compression remain unverified. Manual test artifacts not included in release.
