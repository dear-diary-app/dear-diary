# Private stories

Home has two left-aligned theme-colored story circles between header and books. Own empty circle opens MP4 picker; an active circle opens an authenticated video viewer with controls. Own viewer offers replace/delete. Preview precedes Post. No autoplay/audio on opening. One active story per linked account, 60 seconds max, 20 MiB cap. Storage metadata before build totaled 8,991,252 bytes across 33 existing objects. New bucket is private with a 20 MiB limit and video/mp4 MIME restriction.

Browser checks actual playable duration before preview. Oversize files attempt a local canvas/MediaRecorder MP4 compression only where both MP4 encoding and captureStream are available. Otherwise the user gets a smaller-file request. Output is checked again; nothing is trimmed or uploaded automatically. Device encoding support varies and real-phone audio retention/compression quality are unverified. Upload validates MP4 ftyp and movie/track duration headers again on the server. It rejects malformed/unknown-duration/over-60-second headers, not a full codec-security audit or transcoding service.

Publication is through authenticated story-media only. JWT establishes owner; service-only story_publish requires a linked partner, valid owner path, existing upload and valid duration. Existing row is replaced only after upload and validation succeed. stories RLS permits only owner and linked partner while expires_at > now(). User storage policies permit no direct reads/uploads/signing, so clients cannot create signed links that outlive expiry. The media function checks viewer relation and expiry, downloads through service role and rechecks expiry before returning no-store MP4 bytes. Already downloaded bytes/screenshots/copies cannot be remotely erased. The frontend closes a playing story on expiry and pauses when hidden.

At expiry reads stop immediately. A minute cron deletes expired rows, queues their paths, and calls the cleanup function with the existing cron secret. Files are removed through Storage API. Removal failures leave queue entries for retry. Replacement/deletion queues old files too. Orphans older than one hour are queued by the same tick. Physical deletion can lag by the minute cadence or longer during outages. No push notifications added. No theme-color/safe-area changes.

Validation: rollback-only database tests with synthetic IDs checked owner/partner/outsider RLS, immediate expiry denial, forbidden client publish/direct Storage read, failed replacement preserving old and delete cleanup queue. Actual disposable auth users tested publish, owner/partner authenticated download, outsider 404 and expired 404. All synthetic users/files removed. Deployed cleanup actually removed a separate disposable video via Storage API. UI mocks at 390 and 820 pixels previewed/posted/played a 2-second generated MP4, no overflow, circles in correct strip. Screenshots inspected. Real phone/partner-device playback and compression remain unverified. Manual test artifacts not included in release.

## Fullscreen viewer and reactions

Published stories now render in a viewport-filling native dialog, not the browser Fullscreen API. Browser/OS bars may remain outside the app. No native controls, seek slider, picture-in-picture or context menu in playback. Read-only bottom progress/time, emoji row only for partner story. Autoplay tries sound then muted fallback, with tap video to retry/unmute if blocked. Close ×, swipe down, Escape or ended. Preview retains native controls before posting. Own replace/delete moved beside the Home circle.

Reactions use a new paired, expiry-scoped table/RPC, allowlisted eight emoji, one current partner reaction per story. Owner sees reaction under the circles after Home refresh (minute cadence or return). No pushes/chat messages are sent. Current story expiry must match, so stale/replaced/expired story reactions fail. Reactions cascade/delete/reset with story and replacement. Rollback tests checked partner write/owner read, outsider denial and replacement reset. Synthetic 390/820 video playback checked viewport bounds, autoplay progress, controls absent, reaction RPC and own emoji row absent; screenshots visually inspected. Real-phone autoplay/audio/browser chrome/swipe behavior remains unverified.

## Private story links and cover playback

Share/Copy link in both viewers share an app hash link with owner UUID and exact expiry, not a video URL or token. Login/app PIN and existing backend pair checks still apply. Home validates that exact active story; replaced, expired, invalid or inaccessible links fail. ResumePlace does not override explicit story links with saved route. Back clears link parameters. Native share sheet when supported, clipboard fallback otherwise. Clipboard/share failures are reported. Top-left Back replaces X. Time labels removed; read-only bar stays. Video is top-aligned object-fit cover, so edges may crop rather than letterbox. No theme-color/safe-area changes. Synthetic 390/820 tests checked layout, copy/share payload equality, partner reactions retained, deep-link opening, saved-route bypass and invalid/replaced/missing denial.

## Hold to pause

Pointer-down on non-control story area pauses immediately and captures that pointer. Release resumes only if it was playing before the press and the document is visible. Cancel/lost capture clear the hold too; hiding and unmount still stop playback. Progress derives from video currentTime, so it freezes with playback. Long release suppresses the video's short-tap unmute/start action; swipe-down still closes. Buttons never start a hold. Context menus, touch callout and text selection suppressed only within fullscreen viewer. Tested with actual browser CDP touch events at 390/820: time/bar fixed over a 900ms hold, release advances, touchCancel recovers, Share/Copy/reaction/Back taps pass. Paused-state pixels inspected. Physical phone long-press behavior still needs user confirmation. No theme-color/safe-area/backend changes.

## Familiar story layout and Activity

Single active story means one thin progress segment at the top. Header includes Back, current avatar/initial, owner name and compact age, plus own-avatar badge. Owner bottom tools Activity/Share/Copy/More; More contains Replace/Delete and pauses playback. Partner bottom tools open private chat composer (empty, no automatic send) plus Share/Copy and existing emoji row. No boost/music/mentions added. View is marked only when playback emits playing; paired expiry-scoped RLS/RPC records one viewer, owner can inspect Activity with current reaction. Replacement resets and deletion cascades views. Rollback test checked paired mark/owner read, idempotency, outsider denied and replacement reset. 390/820 synthetic layout and hold tests passed both roles, screenshots inspected. Chat composer route uses existing explicit Send; no story message generated or sent.
