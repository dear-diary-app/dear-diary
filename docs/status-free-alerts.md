# Friend is free alerts

A status UPDATE from any non-Free status (including blank) to Free creates a private dispatch event only when the linked recipient has explicitly enabled `notifications.friendFree` and has not disabled `notifications.chat`. Whitespace/case are normalized for comparison. First-time inserts and repeated Free saves do not alert. Both directions use the same friendship rule. Existing status choices already included Studying.

The category is off by default. The recipient enables it in Settings > Notifications, and separately enables device push. Claims recheck friendship, recipient preferences, the sender's current Free status and a two-minute freshness window. Each event can be claimed once. The worker checks preferences again before each subscription. It sends only a Dear Diary title and a short display-name/is-free-now body, never status history or chat/diary text. Service worker stores it in the existing account-filtered notification inbox, not the chat stream. No read receipts or app unlock are implied.

Delivery is best-effort, not guaranteed. A claimed failed dispatch is not retried automatically, to avoid duplicate alerts. Push TTL is two minutes to limit delayed notices; devices can still delay or drop a push. Alerts already accepted by a push provider cannot be recalled by later opting out. Multiple registered devices may each receive a notice. Existing device permissions, chat mute and category opt-in all apply. Refresh/reopen the app for the new settings UI and service worker.

QA: rollback-only synthetic users test default-off, chat mute, Busy/Studying/blank to Free, repeated Free, reverse direction, late opt-out, stale status, duplicate claim and private table/function permissions. The worker is tested with mocked webpush for eligible/disabled/missing/error states, forbidden endpoints, expired subscriptions and secret-header authentication. No test pushes or real account mutations. UI mocks test save and toggle on/off in paper/midnight. Physical-device delivery is not claimed.
